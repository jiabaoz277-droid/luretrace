# 前端开发技术手册｜路亚问问（正式 H5 阶段）

> 配套：PRD v0.9、通用技术栈手册 V2.1、《前端技术适配声明》、第 1–3 阶段文档。
> 定位：给 AI 的正式前端执行规范；AI 负责把"产品经理操作"翻译成可执行指令。
> 状态：核心链路已验收，本文档指导从"单文件切片"到"正式 H5 前端"的过渡。

## 一、目标与边界

- **目标**：把已验证核心链路的前端，做成可上线演示的移动端优先 H5；复用现有后端，不重写业务逻辑。
- **本阶段范围**：
  1. 单文件 `page.tsx` 拆分组件化；
  2. 补齐加载 / 空数据 / 错误 / 中断 / 恢复状态；
  3. 移动端 H5 体验（触控、安全区、响应式）；
  4. PWA 基础（manifest + 图标）。
- **明确不做**：登录体系、桌面/App/小程序、离线推送、视觉系统大改（待产品经理确认方向）。

## 二、技术栈基线（沿用，不换）

| 项 | 版本/方案 | 说明 |
| --- | --- | --- |
| 框架 | Next.js 16 + React 19 + App Router | 现有基础 |
| 语言 | TypeScript 5 | 类型检查为 A 级底线 |

## 四、后端 API 契约（前端只调这些，不得直连数据库）

| 方法 | 路径 | 用途 | 前端已接 |
| --- | --- | --- | --- |
| POST | `/api/v1/chat` | 对话（SSE 流式） | ✅ |
| GET | `/api/v1/plans/{id}`、`/api/v1/plans?session_id=` | 方案卡查询 | ⬜ 待补 |
| GET/PUT | `/api/v1/profile` | 装备偏好 | ✅ |
| GET | `/api/v1/reports?session_id=` | 战报列表 | ⬜ 待补 |
| POST | `/api/v1/reports/{id}/review` | 确认复盘 | ⬜ 待补 |
| DELETE | `/api/v1/reports/{id}` | 删除战报 | ⬜ 待补 |
| POST/GET/DELETE | `/api/v1/spots` | 收藏钓点 | ⬜ 待补 |
| GET | `/api/v1/insights` | 个性统计 | ⬜ 待补 |
| GET | `/api/v1/health`、`/api/v1/model/status` | 状态探测 | ⬜ 待补 |

### SSE 事件契约（不可破坏）

```text
data: {"type":"chunk","content":"...","session_id":"..."}   ← 0..N 次
data: {"type":"done","session_id":"...","payload":{...}}     ← 结束（成功）
data: {"type":"error","error":{"code","message"}}            ← 结束（失败）
```

- `done.payload` 可能字段：`type`(`plan`/`clarify`/`onsite`/`report`/`insight`/`reply`)、`reply`、`plan`、`missing`、`steps`、`report`、`quick_options`、`insight`。
- 前端解析规则：`chunk` 追加内容；`done` 用 payload 渲染卡片；`error` 显示 `error.message`（不展示内部细节）。
- 会话：首个请求不带 `session_id`，从返回的 `session_id` 记录并回传，保持多轮上下文。

## 五、状态处理规范（A 级体验底线）

每个有网络交互的区块都必须处理四种状态：

| 状态 | 规范 |
| --- | --- |
| 加载 | 消息流用"正在思考…"；列表/面板用骨架或 spinner，不白屏 |
| 空数据 | 给出下一步指引（如"你还没有收藏钓点，说『收藏富春江』即可"） |
| 错误 | 统一"无法连接服务，请确认后端已启动（端口 8003）"；SSE `error` 用其 message |
| 中断/恢复 | SSE 读取失败时保留已收到内容并提示重试；刷新页面后会话可从后端恢复历史（待接 plans/reports 查询） |

## 六、移动端 H5 规范

- 容器：`max-w-md mx-auto`，宽度 >768px 时居中留白，模拟手机。
- 触控：按钮/输入框 ≥44px 热区；快捷选项可横向滚动。
- 安全区：底部输入栏留 `safe-area-inset-bottom`（iPhone 刘海/手势条）。
- 视口：`viewport` 已含 `width=device-width, initial-scale=1`；禁止横向溢出。
- 响应式检查：至少验证 375px（iPhone）与 768px（平板）两档宽度。

## 七、PWA 基础（本阶段最小）

- `app/manifest.ts`（或 `public/manifest.json`）：名称、图标、`display: standalone`、主题色。
- 图标：`public/icon-192.png`、`icon-512.png`。
- 离线壳与服务端推送：暂缓（需产品经理确认）。

## 八、检查与测试

- 每次提交前：`npm run build`（含 tsc 类型检查）+ `npm run lint`。
- 关键交互人工验证：对话流式、方案卡、排障 3 步、战报确认、偏好保存、快捷按钮。
- 不要求前端自动化测试覆盖全部；但 SSE 解析函数（`lib/sse.ts`）建议写纯函数单测（离线）。

## 九、验收清单（产品经理照做）

- [ ] 手机/浏览器打开 H5，对话、方案卡、排障、战报、偏好均可用
- [ ] 断网时输入有明确错误提示，不白屏、不卡死
- [ ] 刷新后重新对话可继续（会话不丢失关键结果）
- [ ] 375px 与 768px 宽度下无横向滚动、按钮可点
- [ ] "我的规律"无数据时显示引导文案而非空白
- [ ] 收藏/战报/偏好的增删改在刷新后仍存在
