# 第 2 阶段技术开发文档｜补全「计划—临场—复盘」闭环（装备偏好 / 临场排障 / 战报复盘）

> 配套文档：《对话式路亚决策助手 PRD（MVP）》v0.9、技术栈手册 V2.1、《技术适配声明》、第 1 阶段文档。
> 本文档只覆盖第 2 阶段，不得提前实现其他阶段能力。

## 一、阶段目标

- **交付范围**（对齐 PRD 的 P0 场景，补全闭环）：
  1. FR-06 个人装备与偏好：保存竿/轮/线/拟饵/不愿用钓法/最大车程/夜钓/涉水；决策时优先使用用户装备
  2. FR-05 临场排障：到达钓点或"没口"后，问一个信息增益问题，给出按顺序执行的 3 步调整（每步含观察时长 + 升级条件）
  3. FR-07 战报与复盘：四类结果（上鱼/有口未中/空军/未出钓）+ 可选字段；生成复盘，用户确认后写入
- **阶段产物**：本地可演示的「计划 → 到水边排障 → 记战报 → 复盘」完整闭环。
- **明确不做**：钓点收藏与提醒（P1）、图片识鱼/环境判断（P1）、海水路亚（P1）、多用户登录、真实天气/钓点/法规数据、相似历史对比（v0.2 个性化深水区）。
- **本阶段打通链路片段**：`出钓方案 → 到达钓点没口 → 3 步调整 → 提交战报 → 生成复盘 → 确认写入历史`。

## 二、技术适配摘要

- 延续第 1 阶段：Python/FastAPI/Pydantic/SQLAlchemy(SQLite)/pytest、Next.js H5、真实模型（DeepSeek）+ 规则兜底、SSE 流式。
- 本阶段启用：新增 2 张表（`profiles`、`catch_reports`），沿用 `create_all` 初始化（Alembic 仍暂缓）。
- 决策引擎、临场排障、复盘的结构化规则均为确定性代码；LLM 只负责自然语言生成（沿用 `llm.py`）。

## 三、数据、资产与状态

- `profiles`（单用户 MVP，`user_id="default"` 唯一）：
  `rods` `reels` `lines` `lures` `avoid_methods`（JSON）、`max_travel_radius`（str）、`night_fishing` `wading`（bool）、`home_location`（str）、`constraints`（JSON）、`created_at` `updated_at`。
- `catch_reports`：
  `id` `session_id` `plan_id`(可空) `result_type`（landed/bite_no_fish/skunked/no_go）`species` `count` `length_weight` `lure` `actual_window` `water_color` `flow` `note`（用户可选）、`review`（复盘文本）`review_confirmed`（bool，默认 False）、`inferred`（JSON，模型推断与用户输入分字段）、`created_at`。
- 对话状态机扩展：会话增加 `mode`（planning/onsite/report）与 `pending`（收集中的字段）。战报的"模型推断"与"用户明确输入"分字段保存（FR-07）。

## 四、API 设计

1. `GET /api/v1/profile` → 偏好（无则空对象）
2. `PUT /api/v1/profile` → 保存偏好（Pydantic 校验）
3. `POST /api/v1/chat`（复用，SSE）→ 意图路由到 planning / onsite / report 三种流
4. `GET /api/v1/reports?session_id=` → 战报列表
5. `POST /api/v1/reports/{id}/review` → 确认复盘写入（`review_confirmed=true`）

统一错误 `{"error":{"code","message"}}`。

## 五、临场排障规则（确定性，FR-05）

- 触发：意图 `ON_SITE_TROUBLESHOOT`，或计划卡"到达钓点/没口"。
- 第一步：只问一个最有信息增益的问题（是否见炸水/追口、能见度、是否已试某水层）。
- 第二步：按信号给出 3 步调整，每步含观察时长与升级条件：
  - 炸水打不到 → ① 缩小拟饵/加快节奏 10min → ② 换水面系 10min → ③ 换标点。
  - 完全无口 → ① 换搜索范围/标点 15min → ② 换水层 15min → ③ 换拟饵规格，仍无口则转场或收工。
  - 跟口不咬 → ① 减速/停顿 10min → ② 换自然色/小一号 10min → ③ 换钓组。
- 安全提示：涉水、雷雨、夜间岸线等风险优先（复用 `detect_hazards`）。

## 六、战报与复盘（确定性 + LLM 生成，FR-07）

- 流程：询问结果类型（4 个快捷选项）→ 记录最小字段 → 可选补充（鱼种/数量/拟饵/水色/备注）→ 生成复盘（哪些判断被验证/可能失效/下次优先尝试）→ 用户确认后 `review_confirmed=true`。
- 复盘文本由 `llm.py` 生成（基于战报 + 关联计划），失败回退模板；未确认的推断不写入长期偏好。

## 七、装备偏好与决策联动（FR-06）

- `decision.build_plan` 接收 `profile`：若用户保存了常用拟饵，方案主拟饵优先用用户装备；保存了最大车程，超限时在风险中提示；保存了不夜钓/不涉水，作为硬约束持续生效。

## 八、前端（纵向切片扩展）

- 对话页新增快捷按钮：`到水边没口`（排障）、`记一下今天的战报`（战报）。
- 新增 `我的` 入口（简单设置页/抽屉）：装备偏好表单（拟饵、最大车程、夜钓/涉水开关）。
- 战报/复盘结果以卡片展示；复盘需用户点击"确认"才写入。

## 九、测试要求

- 第一层 mock：profile 保存/读取、决策优先用户装备、排障 3 步规则（信号分诊）、战报四类结果 + 分字段、复盘确认流转、SSE 端到端。
- 第二层真实冒烟：排障与复盘各一条真实链路；无 Key 时声明待验。

## 十、验收清单

- [ ] 在"我的"里保存装备与"不夜钓/40分钟车程"后，新方案优先用我的拟饵且不超限制
- [ ] 输入"到水边没口"→ 只问一个问题 → 给出 3 步调整（每步有观察时长和升级条件）
- [ ] 输入"记一下今天战报"→ 选"空军"→ 30 秒内完成记录
- [ ] 战报生成复盘后，需点"确认"才写入；可编辑/删除
- [ ] 刷新页面后战报与偏好仍在

## 十一、风险与待确认

- 单用户 `user_id="default"`：真实登录在后续阶段接入。
- 复盘"个性化"为浅层（个人历史规则），相似历史对比留到 v0.2 深水区。
- 待产品经理确认：是否需要图片上传（本阶段不做，留 v0.2）。
