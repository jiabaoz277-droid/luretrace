# 第 1 阶段技术开发文档｜出钓决策最小闭环（Web/H5 纵向切片）

> 配套文档：《对话式路亚决策助手 PRD（MVP）》v0.9、《AI Agent 产品 Vibe Coding 通用技术栈手册》V2.1、《技术适配声明》。
> 本文档只覆盖第 1 阶段。AI 开发时不得提前实现其他阶段的能力。

## 一、阶段目标

- **交付范围**（对齐 PRD 场景 P0）：
  1. 自然语言输入 → 意图识别与槽位抽取（FR-01）
  2. 单缺口追问（最多 3 轮形成首个方案）
  3. 天气/日照查询（FR-02，本阶段 mock 数据 + 统一工具接口）
  4. 出钓决策生成（FR-03，规则引擎 + 鱼种知识）
  5. 方案卡保存与版本化（FR-04 基础版）
  6. 移动端 H5 最小对话界面（纵向切片）
- **阶段产物**：可本地启动、可用浏览器对话并得到出钓方案卡的最小闭环。
- **验收标准**：见第十一节验收清单。
- **明确不做**（防范围蔓延）：临场排障 FR-05、装备偏好 FR-06、战报复盘 FR-07、钓点精确推荐与隐私 FR-08 完整版、安全法规库 FR-09 完整版、真实数据源接入、正式视觉系统、用户登录。
- **本阶段打通的主链路片段**：`输入"明早杭州周边两小时打翘嘴" → 槽位抽取 → 追问缺口 → mock 天气/日照 → 规则决策 → 流式输出方案 + 方案卡保存`。

## 二、技术适配摘要

- 引用《技术适配声明》结论：纵向切片；Python 3.11 + FastAPI + Pydantic + pytest + SQLite/SQLAlchemy + SSE；Node 26 + Next.js 最小切片。
- 本阶段采用：FastAPI、Pydantic、pytest、Git、SQLite+SQLAlchemy、SSE、Next.js+TS+Tailwind（仅最小对话页）。
- 本阶段启用：SQLite+SQLAlchemy（多实体/版本化）；SSE（流式方案生成）；结构化鱼种知识库。
- 本阶段偏离/暂缓：Alembic 暂缓（本阶段 `create_all` 初始化 schema，首个 schema 变更时引入）；模型调用本阶段用规则+模板 mock（无 Key），真实 LLM 冒烟待 Key。
- 开发路径：纵向切片。

## 三、技术栈与模型

- 后端：Python 3.11.16、FastAPI、Pydantic v2、SQLAlchemy 2.x（同步）、pytest、uvicorn。
- 前端：Next.js + TypeScript + Tailwind CSS（最小单页对话）。
- 模型：本阶段无真实 Key，使用 `services/llm.py` 抽象层 + 规则/模板实现；意图识别与槽位抽取用确定性规则（正则 + 词典），决策用规则引擎。真实模型（建议 DeepSeek）接入点为 `llm.py`，验收前补 Key 后切换。

## 六、数据、资产与状态

- 持久化：SQLite（`data/fishing.db`），SQLAlchemy 同步引擎。
- 表 `plans`：`id`、`session_id`、`version`、`location`、`time_window`、`target_species`、`travel_radius`、`conclusion`(go/no_go)、`confidence`(high/mid/low)、`score`(0-100)、`best_window`、`plan_detail`(JSON)、`data_basis`(JSON)、`risks`(JSON)、`status`(active/outdated)、`created_at`、`updated_at`。
- 对话状态机（内存 + 按需持久化到 plans）：`collecting(收集槽位) → clarifying(追问缺口) → ready(生成方案) → confirmed(方案已确认)`；用户纠正信息后旧方案 `status=outdated`。
- 本阶段无图片/音视频资产。

## 七、API 设计

1. `POST /api/v1/chat`（SSE）
   - 请求：`{"message": str, "session_id": str|null, "context": {...}|null}`
   - 事件序列：`chunk`（0..N）→ `done`（含完整结果）或 `error`；`error` 结构 `{"error": {"code","message"}}`。
   - `done` 数据：`{"type":"reply"|"plan","reply":str,"plan":{...}|null,"missing":[...]|null}`
2. `POST /api/v1/plans`：保存方案卡，请求=plan 字段，响应=保存后的 plan。
3. `GET /api/v1/plans/{id}`：查询方案卡。
4. `GET /api/v1/health`：健康检查。

统一错误：`{"error": {"code": str, "message": str}}`；不暴露堆栈。

## 八、Prompt 设计（本阶段为预留）

- 真实 LLM 接入后：`system_prompt`（路亚搭子人格 + 事实/推断/建议分层 + 安全优先 + 最多 3 轮）；`slot_extract_prompt`（正反例，见手册第九节"格式约束三件套"）。
- 本阶段无 LLM 调用，槽位抽取为确定性解析，需兼容多种等价表达（中文序号、口语时间等）。

## 九、验收界面（纵向切片）

- 本阶段需要最小界面（属于正式产品切片）：`frontend/` 单页对话，移动端 H5 风格。
- 功能上限：输入框 + 4 个快捷问题 + 流式消息 + 方案卡展示 + 快捷修正。不做登录、不做多页、不做完整视觉系统。

## 十、测试要求

- **第一层 mock 测试（必跑）**：
  - `test_intent.py`：意图分类；槽位抽取（明早/周末相对时间转绝对日期、地点、目标鱼、距离、约束）；多意图句；歧义消解不静默选择。
  - `test_decision.py`：方案含 ≥5 项（时间/标点/水层/拟饵/手法/调整条件）；安全规则命中（雷暴/强风）时安全提示覆盖鱼口建议；分数附构成因子。
  - `test_chat_api.py`：端到端（TestClient，mock 模型）——追问只问一个缺口、流式以 `done` 收尾、方案卡可保存查询。
- **第二层真实冒烟（待 Key）**：接入真实模型后，用 `curl -N` 验证 SSE 首 chunk 时间、`done`/`error` 收尾；记录模型、耗时、成本。

## 十一、验收清单（产品经理照做）

- [ ] 启动后端与前端后，浏览器打开 `http://localhost:3000`
- [ ] 输入"明早杭州周边两小时，想打翘嘴"，能收到追问（且一次只问一个缺口）
- [ ] 补齐信息后，能看到流式输出并得到"建议去/不建议 + 窗口 + 方案"
- [ ] 页面出现方案卡（含时间、标点、水层、拟饵、手法），并可修改条件后看到"方案已更新"
- [ ] 输入"雷暴天能去吗"，首屏出现安全提示而非鼓励出钓
- [ ] 刷新页面后历史方案卡仍可查看（数据持久化）

## 十二、风险与待确认项

- 模型 Key 未提供 → 本阶段为规则/mock，效果不等于真实 Agent；验收前需补 Key 做第二层冒烟。
- 天气/钓点/法规数据未接入 → 决策基于 mock，不代表真实可出钓。
- Alembic 暂缓 → 首个 schema 变更时引入。
- 待产品经理决定：模型选型（建议 DeepSeek）、数据源与预算、首发城市与对象鱼（本阶段知识库先内置翘嘴/鳜鱼/鲈鱼等 10 种）。
