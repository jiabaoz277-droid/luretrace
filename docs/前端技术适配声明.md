# 前端技术适配声明

> 依据：《对话式路亚决策助手 PRD（MVP）》v0.9、《AI Agent 产品 Vibe Coding 通用技术栈手册》V2.1、当前代码状态。
> 日期：2026-08-25 ｜ 分支：stage-3 ｜ 性质：由"最小验收切片"过渡到"正式 H5 前端"。

## 1. 前端形态判断

- **目标终端**：移动端优先的 H5 / PWA（PRD 明确，后续可复用后端扩展 App、小程序）。
- **当前前端状态**：已有一个 Next.js 单页纵向切片（`frontend/src/app/page.tsx`，473 行），覆盖对话流、方案卡、临场排障卡、战报复盘卡、快捷选项、"我的"装备偏好面板；核心链路已随第 1–3 阶段验收。
- **介入时机**：纵向切片（对话、人工确认本身就是核心交互，不能后端先行）。
- **本声明性质**：核心链路已成立，前端进入"正式化"阶段——把单文件切片重构为可持续扩展的正式 H5 前端，但不改变已验证的后端契约。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| Next.js + TypeScript + App Router | 手册默认 Web 方案，现有代码已基于此，不换框架 |
| Tailwind CSS | 现有样式基础，移动端快速适配 |
| ESLint + TypeScript | A 级强制底线（代码检查 + 类型检查） |
| 复用现有后端 API（`/api/v1`） | 前端只通过受控 API 调用后端，不重复实现业务逻辑 |
| SSE 流式消费（fetch + ReadableStream） | 现有实现已验证，保持事件序列 `chunk* → done/error` 契约 |

## 3. 触发的按需模块

| 模块 | 触发需求 | 本阶段是否引入 |
| --- | --- | --- |
| PWA（manifest + service worker） | 移动端"添加到主屏幕"、离线弱网 | ⚠️ 先做 manifest + 图标 + 基础离线壳，推送/后台同步暂缓 |
| 状态管理库（zustand 等） | 多组件共享会话/消息状态 | ❌ 暂不引入（当前 useState/useRef 够用，重构时再评估） |
| UI 组件库 | 视觉统一 | ❌ 暂不引入（Tailwind 手写，等视觉方向确认后评估） |
| 数据请求库（swr/react-query） | 列表/轮询/缓存 | ❌ 暂不引入（fetch 够用） |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代/偏离 | 原因 | 影响 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| Node 22 LTS | 沿用环境 Node 26 | 环境已装，Next 16 兼容 | 无明显影响 | 工具链出现不兼容时 |
| 正式组件化目录 | 当前为单文件 page.tsx（473 行） | 纵向切片期快速迭代导致 | 可维护性差，需拆分 | 本轮重构即处理 |
| 桌面/App/小程序终端 | 只做移动端 H5 | PRD 移动端优先 | — | 产品确认扩展终端时 |

## 5. 强制底线检查

- **密钥与隐私**：通过——前端不存模型 Key，只读 `NEXT_PUBLIC_API_BASE`（后端地址，非秘密）。
- **前端只通过受控 API**：通过——所有能力走 `/api/v1`，不直连数据库。
- **错误不暴露堆栈**：通过——SSE `error` 事件 + fetch 异常统一转用户可读提示。
- **加载/空/错误/恢复状态**：待完善——当前对话流已处理 loading/error，但"历史战报/收藏/个人偏好"的加载与空态需补全。
- **类型检查与代码检查**：通过（`npm run build` 含 tsc + `npm run lint`），需纳入每次提交流程。

## 6. 需要产品经理决定的问题

1. **视觉方向**：当前为蓝色系占位样式，无品牌色/设计稿。是否提供设计稿或参考产品？（无则我先做一版移动端 H5 代表页给你确认）
2. **PWA 范围**：本阶段是否要做"添加到主屏幕"？（建议做基础版：manifest + 图标，离线缓存和推送后续）
3. **是否需要登录**：当前无登录（单用户 `user_id="default"`），正式前端是否要在视觉上预留登录入口？（MVP 可不做）

**结论**：正式前端继续采用 Next.js + TypeScript + Tailwind，复用现有后端 API 与 SSE 契约；本轮重点工作是**单文件拆分组件化 + 完善移动端 H5 体验 + 补齐加载/空/错误/恢复态**，PWA 先做基础 manifest。以上 3 个待确认项不影响重构开工，仅影响视觉与 PWA 细节。
