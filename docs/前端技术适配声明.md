# 前端技术适配声明

> 依据：PRD v0.9、通用技术栈手册 V2.1、《通用前端技术栈手册》V1.0、当前代码（stage-3-frontend）。
> 日期：2026-08-25

## 1. 项目判断

- **产品类型**：对话式路亚出钓决策助手（LLM Agent + 工具调用，多轮对话 + 人工确认）。
- **主要用户**：入门路亚用户、周末型城市钓手、不熟悉当地的钓手（PRD 5.1）。
- **主要终端**：移动端优先 H5（PRD），兼顾桌面浏览器（最大宽度居中模拟手机）。
- **新项目或已有项目**：新项目；前端已有 Next.js 单页纵向切片，随第 1–3 阶段验证，现进入正式化。
- **本阶段业务目标**：把单文件切片重构为可扩展的正式 H5 前端，套用 Daiwa 视觉风格，补齐加载/空/错误/恢复态。

## 3. 技术选择

- **框架与版本**：Next.js 16.3.2 + React 19.2.8（App Router），与手册参考基线一致。
- **语言**：TypeScript 5，strict；外部接口类型集中 `types/api.ts`。
- **样式与组件策略**：Tailwind CSS v4 + `@theme` 语义变量（daiwa/ink/paper/surface/line/accent）；组件按业务功能组织。
- **数据请求与状态策略**：`fetch` + 集中 API 层（`lib/api.ts`）；会话状态 `useChat`，偏好 `useProfile`；未引入 TanStack Query/Zustand（当前复杂度不需要）。
- **流式通信策略**：POST + Fetch Streaming（SSE 解析为纯函数 `lib/sse.ts`）；事件序列 `chunk* → done | error`。
- **表单方案**：原生受控组件（偏好表单简单，未引入 React Hook Form）。
- **测试方案**：Vitest + React Testing Library（SSE 解析、组件状态）；Playwright 暂缓。
- **部署环境**：本地开发（端口 3002），正式部署见部署手册（standalone 输出）。

## 4. Agent 状态

- **后端状态 → 前端状态映射**：本产品为短对话（非长任务队列），前端核心状态简化为 `loading`（等待响应）/ `streaming`（流式输出中）/ `done`（成功含卡片）/ `error`（失败）。对话以 SSE `done`/`error` 为事实来源。
- **等待用户确认方式**：追问（`clarify` + `quick_options`）、战报复盘确认（`report` + 确认/取消按钮）——均为后端驱动，前端只渲染。
- **取消、重试、断线恢复方式**：当前为短请求，无长任务取消；断线时保留已收到内容并提示重试；刷新后会话可从后端 `plans`/`reports` 查询恢复（待接入）。
- **任务 ID 和恢复入口**：`session_id` 由后端返回并回传，维持多轮上下文。

## 5. 页面与产物

- **核心页面**：单页对话（默认首页）＋"我的"装备偏好底部面板。
- **核心业务闭环**：`对话 → 出钓方案卡 → 临场排障/战报复盘 → 我的规律`。
- **产物类型和预览方式**：文本卡片（PlanCard / StepsCard / ReportCard / InsightCard）；无图片/音视频产物（后续阶段）。
- **响应式目标**：375px（手机）、768px（平板）两档；触控目标 ≥44px；底部安全区适配。

## 6. 偏离本手册的地方

| 偏离项 | 原因 | 影响 |

| 目录用 `components/* + hooks/ + lib/ + types/`，未用 `features/` | 已有单页项目，按业务组件就近组织 | 无功能影响，后续多业务时再迁 features/ |
| 暂未引入 Playwright E2E | 核心闭环由后端 pytest + 人工浏览器验收覆盖 | E2E 自动化延后 |
| 曾用 emoji 作图标 | 已计划改为 Lucide | 需整改 |
| `package.json` 缺 `typecheck` 脚本 | 依赖 build 内 tsc | 需补 `typecheck` 脚本 |
