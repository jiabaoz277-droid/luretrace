# 技术适配声明

> 依据：《对话式路亚决策助手 PRD（MVP）》v0.9 +《AI Agent 产品 Vibe Coding 通用技术栈手册》V2.1
> 日期：2026-08-25

## 1. 产品形态判断

- **产品类型与核心任务**：对话式路亚出钓决策助手（LLM Agent + 工具调用）。用户用自然语言描述出钓目标与限制，产品综合实时条件、对象鱼规律与用户装备，给出可执行的出钓方案，并支持临场调整与战报复盘。
- **核心交互**：多轮对话 + 分阶段确认（方案卡确认、战报确认）+ 动态工具调用（地点解析 / 天气查询 / 日照查询 / 规则检索，均在白名单内）。
- **开发路径**：**纵向切片**。对话、追问、方案卡确认本身就是 Agent 能力的核心，不能把 UI 当作最后的"展示壳"；且 PRD 明确"移动端优先 H5/PWA"，需要最小真实界面做端到端验证。
- **当前阶段范围（第一阶段）**：打通"出钓决策"最小闭环——自然语言输入 → 意图识别与槽位抽取 → 单缺口追问 → 天气/日照查询 → 出钓方案生成 → 方案卡保存与修改 → 移动端 H5 最小对话界面。临场排障、战报复盘、装备偏好等 P0 功能按 PRD 交付阶段拆到后续阶段，不提前实现。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| Python 3.11.x | 环境已有 3.11.16，符合手册基线，用于业务/Agent 能力 |
| FastAPI | 把对话、决策、计划卡做成可测试和可调用的 API |
| Pydantic | 校验接口请求与模型结构化输出（槽位、方案卡、状态） |
| pytest | mock 自动化测试，覆盖状态流转、错误路径与解析器 |
| Git | 当前非仓库，新建项目时初始化并配 `.gitignore` |
| 模型官方 SDK / 兼容接口 | 调用 LLM；本阶段模型选型见第 6 节待确认项，开发期 mock |
| 移动端 H5 前端 | 正式前端选 Next.js + TypeScript + Tailwind（第一阶段仅做最小对话切片） |

## 3. 触发的按需模块

| 模块 | 触发需求 | 本阶段是否引入 |
| --- | --- | --- |
| SQLite + SQLAlchemy + Alembic | 用户、装备/偏好、方案卡（版本化）、战报等多实体关系、历史记录与并发修改 | ✅ 本阶段引入（SQLite，生产再评估 PostgreSQL） |
| SSE | 方案生成是长耗时流式输出，需逐步展示模型内容 | ✅ 本阶段引入（`chunk` → `done`/`error`） |
| 结构化知识库（JSON/SQLite，非向量检索） | 10–20 种淡水路亚对象鱼的适温、水层、拟饵规则 | ✅ 本阶段以结构化规则引入 |
| 外部工具（天气/日照/地点/规则） | FR-02 实时条件查询 | ⚠️ 本阶段用 mock 数据 + 统一接口，真实数据源验收前接入 |
| 图片/文件存储 | 战报照片（FR-07 可选字段） | ❌ 暂缓（v0.2 图片识鱼再引入，MVP 战报先文本） |
| Chroma / RAG | 无大规模文档语义检索需求，鱼种知识规模小可结构化直接检索 | ❌ 不引入 |
| 任务队列 | 当前为短请求 + SSE，单进程可可靠完成 | ❌ 不引入 |
| OCR | 无扫描件识别需求 | ❌ 不引入 |

## 5. 强制底线检查

- **密钥与隐私**：待处理（模型 Key 未提供，开发期用 `.env` 占位 + mock；`.env` 入 `.gitignore`，只提交 `.env.example`；Key 只由后端读取，不入前端/仓库/日志）
- **数据与任务可恢复**：通过（方案卡、用户偏好、战报全部持久化到 SQLite，进程重启可恢复；关键人工确认点持久化）
- **输入输出校验**：通过（Pydantic 校验请求与模型输出；模型输出"标准格式 + 确定性解析 + 强校验"，校验失败有限重试，仍失败走统一错误）
- **错误与日志边界**：通过（统一错误响应，SSE 失败以 `error` 事件返回统一结构；不向用户暴露堆栈；日志不记录 Key 与敏感原文）
- **测试与真实模型验收**：计划为双层测试——mock 自动化（每次必跑）+ 真实模型端到端冒烟（验收前必做，无 Key 时明确标注待验，不用 mock 冒充）；流式接口用 `curl -N` 验证 `done`/`error` 收尾
- **安全优先于鱼口**：通过（雷暴/洪水/强风/高温/夜钓风险命中阈值时，安全提示覆盖鱼口建议，此规则为确定性代码阈值判断，不依赖模型自觉）

## 6. 需要产品经理决定的问题

以下问题按 PRD 第 20 节"待确认产品决策"整理，**不会阻塞第一阶段开发**（开发期一律用 mock / 合理默认值推进），但在进入真实冒烟与验收前需确认：

1. **模型 Key 与选型**：PRD 未指定模型。建议默认 **DeepSeek**（中文理解好、成本低，用于对话与结构化输出），备选火山方舟（本机已有豆包环境）。需要产品经理注册并创建 API Key，验收前提供。
2. **数据源与预算**（PRD #4）：天气、地图、钓点、法规数据供应方式与预算。开发期用 mock，验收前需确认至少一家天气数据源。
3. **首发平台**（PRD #1）：建议按 PRD 默认采用移动端 H5/PWA；若改小程序/原生 App，需调整前端终端选择。
4. **首发城市与对象鱼**（PRD #2）：决定钓点覆盖与知识库首批 3 个对象鱼范围，建议先选 1 个城市内测。
5. **是否给出具体公开钓点**（PRD #3）：默认 MVP 只给"水域 + 标点类型"，不给敏感精确点位；如要求给具体钓点，需增加钓点核验与隐私合规成本。

**其余问题（商业模式、品牌人格等）不影响技术实现，可延后。**

---

**结论**：第一阶段采用「Python 3.11 + FastAPI + Pydantic + pytest + SQLite/SQLAlchemy + SSE + 移动端 H5 最小纵向切片」，开发路径为纵向切片，数据与模型 Key 开发期 mock、验收前补齐。若以上 5 项确认无误（或暂按建议默认推进），我将生成第一阶段技术开发文档并开始开发。
